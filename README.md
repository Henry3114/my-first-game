# 麦间 · 街角烘焙日记 v2.0

可直接游玩的中文单人烘焙店经营游戏。没有强制引导，从第一天开始自由经营。营业流程为 **确认需求 → 接单 → 排产 → 取货处理 → 包装 → 交付**。

## 游玩与发布

GitHub Pages 地址：<https://henry3114.github.io/my-first-game/>。仓库 Pages 使用 main 分支的根目录；推送生成的 index.html 后由 GitHub 自动构建，实际发布状态以仓库 Actions / Pages 为准。

也可下载根目录 **index.html**，用浏览器直接打开。它已内嵌代码、样式与插画，不需要服务器或外部网络。

## 经营流程

- 开门前选择最多三款菜单，采购面粉、黄油和牛奶。原料可以留到明天，准备阶段没有营业倒计时。
- 每盘制作六份。点击备料，揉面四秒后手动装入空烤箱；指针进入绿色的金黄区间时手动出炉。提前出炉或烤焦会降低品质，影响评价和实收。
- 营业时间 09:00–18:00，约 270 秒（四分半）。最多同时接三张订单，只有一张出餐台；可以暂停，或礼貌婉拒暂时接不了的客人。
- 点击人物或姓名选中顾客，询问用途与预算，再接单或推荐替代品。订单会有普通纸袋、吐司切片、温热、礼盒、草莓装饰等具体要求。
- 订单夹中“取货到出餐台”会实际占用库存。根据需求切片或装饰，再选择纸袋或礼盒。包装要花零钱，完成后点击交付，或拖到场景中正确的顾客身上。
- 未聘前台时不会自动接单、出售或交付；客人等太久会离开。询问需求本身不会固定奖励小费，评价由烘焙程度、新鲜度、交付速度和需求完成度共同决定。
- 取消或超时会尽量将已取出的产品放回面包架，已花包装费用不返还；陈列空间不足时会产生损耗。
- 预订占用一个订单位，要求六份商品与礼盒，14:00–16:00 由实际取货员来取。可提前备好，也需考虑新鲜度，逾时不会产生收入。
- 天气、招牌和周末影响到店频率。街坊早餐日增加熟客及分享需求，周末下午茶和点心分享日带来两份礼盒订单。
- 获得好评的出餐累计配方熟练度。6 份后可花 ¥80 改良，18 份后可花 ¥160 升为招牌；每级缩短两秒烘焙，售价分别提高 ¥1 / ¥3。已经接下的订单保留原报价，正在烤的批次保留原时间。

## 经济与存档

采购原料时支付零钱并增加原料；备料时消耗原料、计入材料成本，不会再扣一遍零钱。包装和水电工资计入费用。营业利润为实收加清售与奖励、减消耗材料和运营费用；设备、研发、配方改良属于投资，另计现金流。

打烊不会自动完成未交付订单，也不会免费完成在制批次。在制批次会损耗，成品根据品质折价清售，原料留到次日。经营困难时可获得街坊互助，避免死档。

进度自动保存在当前浏览器的 localStorage。域名、端口、设备不同不会共享存档；设置中可导出 / 导入 JSON 备份。v1 / v1.1 的零钱、天数、口碑、配方、设备、熟客关系及已支付批次可迁移到 v2；旧的临时顾客重新进场。后台标签页、暂停和弹窗均停止时间，离线不会自动经营。预览禁止存储时仍可游玩，需导出备份。

## 开发与验证

运行不需要安装依赖；开发服务需要 Python 3：

```sh
npm start
# 提供 0.0.0.0:8000 静态服务
```

需要 Node.js 18+ 执行构建与测试：

```sh
npm run build
npm test
```

浏览器集成测试需要 Playwright 与 Chromium（当前云环境已安装）：

```sh
npm ci --ignore-scripts --cache /tmp/maijian-npm-cache
# 如无系统 Chromium：npx playwright install chromium
npm run test:ui
```

逻辑测试覆盖十天连续经营、库存守恒、厨房工序、品质与新鲜度、订单容量、切片装饰包装、超时取消、预订取货、员工、配方成长、日历、成本与存档迁移。浏览器测试覆盖真实操作链、暂停、导入导出、旧存档、预订、响应式布局及无网络、禁止存储的独立预览。截图位于忽略的 test-results/，可用 CHROMIUM_PATH 指定浏览器路径。

源码：game.js 是经营引擎，app.js 是界面与存档，scene.js 是保留状态的 Canvas 场景，art.js / assets/ 提供插画。样式为 styles.css、scene.css 和 work.css，HTML 骨架为 scripts/page.html。修改源码后必须执行 npm run build，连同生成的 index.html 一起提交。
